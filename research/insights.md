# Insights

Data/EDA findings, error analysis, what generalises. Append, do not rewrite.

## 2026-09-25 00:45 IST - initial EDA (train labels only; test = row counts and country counts only)

Sizes (rows): train S1 2,206,821 | train S2 5,034,616 | train S3 5,285,603 | test S1 1,732,544 | test S2 4,887,273 | test S3 5,082,316.
Parquet copies in cache/raw/*.parquet (zstd, ~1 GB total, 2-5 s to load each). Always read these, never the TSVs.

Labels:
- Every pool (S2/S3) record matches AT MOST ONE S1 entity (7,638,365 gold pairs, 7,638,365 unique pool ids). Assignment constraint is exact.
- No gold pair crosses countries. Blocking within country loses nothing.
- Match count per S1: 0: 5.6%, 1: 5.4%, 2: 17%, 3: 24%, 4: 22%, 5: 15%, 6: 7.5%, 7+: 4%. Mean 3.46. Singletons are a small share; recall matters as much as precision for most entities.
- 26% of pool records match nothing (distractors). S2 and S3 contribute about equally to gold pairs.
- Countries: train US 60% / India 40% of S1. Test India 47% / US 38% / France 15% (259k S1, ~1.4M pool). France absent from train.

Noise looks generated by a fixed set of operators (seen in sampled clusters):
- Name: website form (mvdata.com, starswelfaresociety.com = concatenated lowercase name + .com), acronym (SWS), honorific prefix (Mr, Smt, Shri), junk prefix (***, --), "formerly:"/DBA prefix with a different name, filler word (Center, Partners, Corp), digit-for-letter typos (Michae1ine), transposed letters (Crumrnie), case changes, legal suffix added/removed/reordered (Llc Deluca Ace Crumrine).
- Address: state in native script (Telugu, Devanagari), state codes (TG, MH, OH) vs full names, city aliases (Poona/Pune), house-number formats (Hno. 102, Door No 0102, #422, NO 422), component reordering, extra locality (SHEFFIELD TWP, PO BOX), missing components, literal "None", truncated or altered numbers (634 vs 6345), city typos (Jeffrson).
- Names in native script also occur (S2 row: Devanagari business name).

Implications:
- House number + street tokens + normalized name tokens are the strongest blocking keys.
- Mappings (state code <-> name <-> native script, city aliases) can be LEARNED from train gold pairs instead of hand-written; France needs a small hand-written fallback.
- Website-form and acronym names need dedicated features (compare against the space-free name, and against initials).

## 2026-09-25 - generator operators and leakage checks (independent agent, train only)

Leakage checks (all gold pairs): entity_id numbers carry no signal (S1 vs matched pool id correlation 0.00014; mod-k agreement at chance; distractor and matched ids same mean). File row order carries no signal (correlation 0.001; clusters not adjacent). Never add id or row-position features.

Operator rates per gold pair (27,629 pairs, 8,000 S1): address uppercased 30%, native-script address 9.0%, native-script name 7.4%, case-only name change 5.9%, website form 5.2% (always ".com"), token reorder 5.0%, identical name 4.6%, address "None" 4.5%, junk prefix 2.5%, digit-for-letter 1.9%, formerly/DBA/aka/trading-as 1.3%.
Prefix vocabulary is small: the, m, mr, shri, sri, dr, smt, and junk marks @ # *** -- >> ... [ (.
House numbers use about 20 templates: #N, no N, no. N, door no N, h.no N, plot no., flat no. and variants.
Word-split operator: words broken with a space ("Li mited", "Pri vate", "Ce nter"); the space-free key undoes it.
About 15 name operators and 8 address operators, each with a small vocabulary: normalization should invert each one explicitly, with one CV ablation per operator.
