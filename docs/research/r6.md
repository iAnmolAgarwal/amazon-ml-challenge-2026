# r6: learner and stacking

## Verdict
A leak-free stage 3 is the one learner/stacking lever with a significant gain. It uses S1-side competition features of
the stage-2 probabilities and is trained only on the uncertain band. Measured: +0.00062 on the 10% sample, trained on
8% of entities (SE 0.00004, 5/5 folds; India +0.00069, US +0.00058). Expected LB about +0.0005 (US/India); France
unknown. Confidence medium: the label-free test guard for this change is still pending (see the end). Nothing in this
lane moves the LB toward 0.985; the learner is not where the 0.02 gap is.

## Evidence (all measured on the shared 10% sample: 220,678 S1, 9.80M pairs; 5 harness folds; rk.decide with rival_out)
Setup facts:
- p006 is sharply separated. 8.51M pairs have p006 < 0.001 and hold 94 positives. The band 0.001 <= p006 < 0.999
  holds 771k pairs (228k positives). Stage 3 is trained and applied only on this band; other pairs keep p006.
- The stage-1 band st1_p >= 0.001 keeps 14.4% of pairs and 99.991% of positives; none of the 68 lost positives reaches
  p006 > 0.5. Full-train band table: 14.12M pairs, 7.49M positives. Training stage 2 on this band costs about 1/7.
- Learning-curve anchor (shared baselines): pb (006 features, 8% of entities) 0.97373, p006 (40%) 0.97443. So 5x
  more entities is worth +0.0007, and 40% -> 100% should add roughly +0.0005 more (derived, log-linear).
  The test model already trains on 100%.

- S1-side features (per S1, from p006 of its own candidates): rank, gap to top, best other, margin, sum of the others'
  p, n >= 0.5, n >= 0.1, gap to next and previous. Pool-side (C): best other S1, margin, sum of others, n >= 0.1
  others, n S1, over the full train graph.
- Reading: refitting on top of p006 adds nothing (A). The whole gain is the S1-side context (B = C). About 60% of it
  comes from the sums/counts, i.e. the expected-match-count context (B2 keeps 0.00024).
- Robustness (C): rival=None in both arms gives +0.00061 (SE 0.00008, 5/5). By true-match count: t=0 -0.0006
  (12,320 S1), t=1 +0.0009, t=2 +0.0008, t=3 +0.0006, t=4 +0.0006, t>=5 +0.0008. Band logloss 0.1182 -> 0.1135.
- Leakage and how it is avoided: an S1-side feature of (s, x) uses only p006 of s's own candidates, all scored by the
  fold model that never saw s's fold. That is standard out-of-fold stacking, with no rival-probability path. The
  pool-side features are the only ones that read rival S1 probabilities from other fold models, which trained on 40%
  of this fold's entities: the same indirect label path as today's stage-2 cp_* features and the decision's
  rival_out. They add nothing, so the recommendation is B without them. If a pool side is ever wanted, make it clean
  this way: per fold, train two models on complementary halves of the other folds and score each rival with the half
  that never saw it. No rival probability then comes from a model that saw the rival or the scored fold, which is
  exactly the test situation. Cost: 2x stage training.

The test stage 2 is not sharper than OOF. It has about 1.5x more uncertain pairs per S1 (France 1.9x), which fits the
denser decoys. Band-level changes such as stage 3 act on more pairs on test than in CV, in both directions, so the
test guard decides.

Negative results (measured):
- S1-level stacker for "no true match": an out-of-fold LightGBM on 17 S1 aggregates beats prod(1-p) in logloss
  (0.0205 -> 0.0192). Used as P(no match) in the decision it gives -0.00002 (0/5 folds); the geometric mean gives 0.00000.
- Multi-threading on the oversubscribed A: num_threads=3 wasted about 7x CPU in OpenMP spin-waits; num_threads=1 is
  faster (note added to research/insights.md).

## Build spec (stage 3, arm B)
- New src/er_feat6.py (a side-car like er_feat4): the S1-side features above from cache/oof/006_stage2.parquet (train)
  and cache/oof/test_006_stage2.parquet (test), keyed by (s1_idx, pool_idx). Restrict to p >= 1e-4 to save memory.
- Attempt 008_stage3:
  - features = the 006 set + p006 + feat6 (9);
  - fit and predict only on band pairs (0.001 <= p006 < 0.999), all other pairs keep p006;
  - CV by writing an OOF parquet, then er_eval --from-oof;
  - test: train on all train band pairs (about 7.7M), predict the test band (about 6.6M).
- Compute on one 8-core/64 GB machine: feat6 about 5 min per split; CV about 15 min at 80% of entities (6.2M band rows
  per fold); test about 10 min. Peak about 15 GB (band-only matrices; never load the 98M-row frame).
- Rounds: 300 and 600 are equal within noise; use 300.

## Risks and interactions
- Test shift: the sums/counts carry the gain, and test has 1.5x more mid-probability decoy candidates per S1. This is
  the mechanism that made "coherence" emit decoys. Ship only if the test guard (pending) keeps the house-conflict share
  and pairs per S1 near 006. The fallback is B2 (rank features only, +0.00024).
- t=0 S1 lose 0.0003-0.0006 (slight over-emission on singletons); watch the empty rate on test.
- Interacts with any stage-2 change (feat5 name specificity, house_rel): stage 3 must be rebuilt on the new stage-2
  OOF. Its gain may shrink as stage 2 improves.
- The stage-2 OOF was trained at 40%, test stage 2 at 100%. The sharpness table shows no sharper test stage 2, so no
  consistency fix is indicated.
