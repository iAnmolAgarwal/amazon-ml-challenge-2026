## 4. Build spec (needs human approval for src edits)
1. **K9 keys** (exact code `keys_all.py`, function `key`). Columns from norm/{split}_{s1,pool}: country_n, name_core,
   name_join, name_skel, name_fl, house, nums; nulls -> "". Keys: all countries p6n, njn, p8, sk, fl, skh, tt;
   India also th; US also tn. p6n = name_join[:6] | n and njn = name_join | n for every number n in nums
   (name_join >= 6 / >= 3 chars); p8 = name_join[:8] (>= 8); sk = name_skel (>= 3); fl = name_fl; skh = name_skel |
   house; tt = any two distinct name_core tokens; th = name token (>= 2 chars) | house; tn = name token | any number.
   Keep a key value only if <= 50 S1 and <= 50 pool records of the country carry it (counted over the whole split);
   pairs = owner S1 x pool sharing it; union over keys.
2. **Reverse text retrieval** (`rv.py text 5 <split>`, MAXDF=0.02): view = name_core + " | " + addr_norm; char
   3-gram CountVectorizer(min_df=2, max_df=0.02) fitted on the split's pool, sublinear tf, idf ln((n+1)/(df+1))+1, L2
   (as er_retrieve). Queries = pool records whose max probability in the current build is <= 0.5; index = S1 of the
   same country; top 5 by cosine (sp_matmul_topn). Train: keep pairs whose S1 is an owner.
3. `er_newpairs.union`: add both sources to the name/address retrieval pairs before the anti-join with existing
   candidates (word_sim 0 for key pairs, the reverse similarity otherwise). Nothing else changes: same feature
   scripts, same 010 route models (no refit), p > 0.001, lexical gate, decide.
4. Compute (M, 4-core F): test keys 2 min; test reverse text ~65 min on 4 threads (4.14M queries); features for ~40M
   new test pairs ~12 min; scoring 2 min. On 8 cores about 45-60 min. Peak ~16 GB. Train: keys 1 min; reverse
   text must query all 2.92M unclaimed train pool records (93 min on 6 threads of a loaded A).
5. Full-CV paired delta will be ~1/10 of the sample delta (route pairs exist only for the owner sample in train).

## 6. Rewrite review (src/er_keys.py, src/er_rtext.py, er_newpairs.py VIEWS/EXCLUDE_OLD, attempts/024_keys)
Compared line by line with my measured code (`keys_all.py`, `rv.py`, `gen_eval.py`; copies in the Mac scratchpad).

**er_keys.py: equivalent.** Same nine keys, same length rules, cap 50 per key value counted over the whole country

empty numbers dropped. Only difference: tt skips names with > 12 distinct tokens (mine had no bound); negligible.

**er_rtext.py: two differences, one matters.**
1. MATTERS (train/CV only): with --queries the index is restricted to the queried S1, so on train every unclaimed

   more pairs with inflated ranks, so the train CV is not the test behaviour (probably optimistic). Test is unaffected.
2. Minor: the vectorizer is fitted per country (idf and the 2% max_df per country); I fitted once on the whole
   split's pool. Unmeasured; keep mine to reproduce +0.00027.

- Anti-join = train_cand/test_cand + OLD pairs (023_comb). Route-union pairs that were scored <= 0.001 are not
