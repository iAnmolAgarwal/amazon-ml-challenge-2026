## Rewrite review (src/er_gen.py, src/er_comb.py, src/er_pool.py, attempts/023_comb; read-only, 26 Sep)
Compared with what 020_gen / 021_comb actually used (gf.py-gf6.py, gen_step.py, comb.py on A). er_comb.py, er_pool.py
and 023_comb/train.py match comb.py: same band 0.003-0.997, same base files and exclusions, same 11 PC columns, same
params (255 leaves, min_data 300, lr 0.05, 800 rounds, ff 0.9, bagging 0.8/1, l2 10, seed 42), same init_score
logit(p) clipped at 1e-6, US/India only, France untouched, `has` split for route pairs. I found no leakage: gen
features are label-free and pair-local, both models are OOF on the harness folds, pool-side features come from OOF p.
All the gain risk is in er_gen.py. Differences, most harmful first (impact not measured; G):
1. No accent folding. Names and address words are tokenized as `lower()`, so "Cénter" vs "Center" becomes a
   one-sided token pair with a mid-token edit. In 020 all tokens were accent- and script-folded. This shifts every
   name feature (ed_*, one_swap, typo, unk, reorder, joinsplit, first/last token, fill_*, legal ids, aw_s/aw_p) on a
   very common true-noise operator. Fix: use `er_norm.fold`, the repo's own fold (no new dependency).
2. best_edit has no cutoff. It always returns the closest pair of unrelated tokens (distance 7-8), and edit_kind flags
   are then set on noise. In 020 the pairs were limited to Levenshtein <= 2 and length difference <= 2, and features
   were -1 when there was none. Fix: add the cutoff and default the kinds to -1.
3. Number operations are symmetric and not zero-aware:
   - op_code and trunc_last/drop_first treat "pool added a digit" the same as "pool dropped a digit". In 020, pool
     truncation had gold 0.68-0.80 and pool extension 0.09-0.17: opposite signs.
   - `abs(d) <= 2` catches leading-zero variants ("02215" vs "2215", d = 0) as a +-1/2 shift before the leading-zero
     test.
   - Exact-string multiset matching makes 02215/2215 unmatched, which also corrupts keep_share and first/last_eq.
   Fix: make the codes directional, test leading zeros first, match numbers modulo leading zeros.
4. The secondary-number op/delta is taken on A[0], which is often the primary house itself, paired to the
   numerically nearest number. In 020 this was k_op_sec/k_d_sec: the first changed number other than the primary
   house, paired by the best operation. k_d_sec was the #1 or #2 gain feature, and k_op_sec = +D is the decoy
   signature (gold 0.02 vs p 0.14). Also, h_op compared the parsed pool house only; 020 matched the S1 house against
   every pool number and used -2 for "primary house absent from the pool".
5. prefix_drop/prefix_add are reversed. The rewrite codes "first token dropped". 020 had g_pre_drop = number of
   trailing core tokens dropped (the truncation operator: "Foot" for "Foot & Ankle Clinic", "Eastern Choice" for
   "Eastern Choice Farms LLC"), and drop_pos only when exactly one token was dropped.
6. Missing 020 inputs with high gain: g_nSA/g_nPA (count of one-sided tokens; top 10), m_unklen (length of the longest
   unknown token; top 15), m_ljs/m_ljp (core-name lengths; top 15), g_acr (acronym letter change: TXD -> BXD, LN ->
   LG), g_d (signed delta when exactly one number changed; num_delta is unsigned).
7. Smaller:
   - legal id takes the last legal token (020: first) and "incorporated" is not mapped to Inc; there is no lg_eq;
   - web_p misses @handle / #handle forms (@brooklynregional);
   - frac = "'/' present on one side" fires on almost every India address (214/3); 020 used the 1/x fraction change;
   - the "<NULL>" token inside an address was a separate cue in 020;
   - hlet (house letter suffix) lacks the "S1 has none" condition;
   - comp_jac skips component 0, but the generator shuffles component order; the patch uses all non-numeric
     components;
   - ed_end should be "within the last 2 characters" (r1: decoy typos edit the token end).
Patch: 86 columns (the 77 of the rewrite plus d11, acr1, n_so, n_po, unk_len, core_ls, core_lp, lg_eq, null_tok).
