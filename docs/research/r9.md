# r9 - fresh eyes on the raw records (generator reverse-engineering)

## 1. Verdict
The decoy ("sibling") generator is exactly identifiable, and 006 cannot see it. Every unmatched pool record I sampled is a near-copy of an existing S1 entity: the house number is shifted by d in D = {+1,+2,+3,+4,+5,+7,+9,+11,+13,+21}, and/or one name token comes from a fixed decoy vocabulary ("holdings", "group", "westgate", "private" and so on). The test's 1.9x decoy excess is exactly this operator: 1.94x at every d in D in US, with background deltas unchanged. France shows the same spikes.
Recommendation: add label-free house features (signed delta, delta-in-D, leading-digit drop) and label-free name-marker scores to stage 1 and stage 2.
Measured so far is a hard rule on top of 006, not the learned features: +0.0008 to +0.0010 US on train decoy density, but it hurts India.
Expected LB gain (derived): US about +0.0015 to +0.002 on test (2x the decoy density), France plausibly more, India needs the learned feature. That is roughly +0.001 LB. Confidence: high that the signal is real and transfers; low-to-medium on the size, because the learned-feature CV had not finished (2.5).
This alone does not reach 0.985. The remaining loss is dominated by blocking misses (a third of FN) and by empty-address records whose name is shared by several S1 (50% of S1 have a name twin), which are largely irreducible.

## 2. Evidence (measured on train unless labelled otherwise)

### 2.1 Structure seen in the raw records
- Per-source counts: S2 matches per S1 run 0..5 and S3 matches 0..6, with identical distributions in US and India. They are independent except for an excess at (0,0): 5.6% observed vs 1.6% under independence.
- Source templates (US): S1 is Title case with full street words and state code; S2 is UPPER case, abbreviated or full, state code; S3 is Title case with abbreviated street types and full state name. An S3 "pseudo-word dba/fka/t/a <exact S1 name>" record copies the S1 address verbatim, in the S1 template.
- Source-level shared noise: all S2 (or all S3) records of an entity share the same corruption ("SPRINGFIELD CTIY", "##21", an inserted "A-411"/"369", "0733", "61A"). Decoys at the same address share it too ("##4321" on a decoy and a true S3), so the noise is keyed by address, not entity. This is why a pool-pool coherence signal cannot separate same-address decoys, which matches the known coherence trap.
- Name replacement: some true matches carry a whole-name pseudo-word ("Ectohalolyra", "Dovadeltanex", "Bélocira"), a single token built from a small syllable inventory shared with the dba prefixes. Same-address decoys instead carry realistic multi-token names ("Kakalina Evan National").
- 50% of S1 share their space-free name with another S1 of the same country. Empty-address pool records with an identical name match only 29% of the time; `nf_p_s1` covers this. It is 2,277 of ~6,200 retrieved FN on the quick subset and is mostly irreducible.
- Leak probes (negative): the "(ID: nnnnn)" name tag (0.3% of pool records) is random. Records sharing a tag map to different S1, and the tag never matches an S1 id. The earlier insights already rule out id and row-order signal.

### 2.2 House-number shift (10% sample, 9.8M pairs, name-similar pairs n_tset >= 80, both numbers parsed)
- Non-matches spike at exactly hd in D: 13.6k-15.8k pairs each, vs 1-3k at every other delta, including all negative ones.
- The match rate at D (excluding +1/+2) is 1.1-2.0%, vs 7-13% at other non-zero deltas.
- True-match number noise is different: +-1/+-2 symmetric (~1.8k matches each), and leading-digit drops (hd = -100, -1000, -10000; `house_prefix` misses these because it tests prefixes only).
- 006 errors on the sample: FP 4,849 = hd 0: 2,018, hd in D: 1,050, missing: 901, other: 869. FN 45,851 = not retrieved: 14,837, missing house: 13,289, other delta: 10,261, hd 0: 4,906, hd in D: 1,409, +-1/2: 1,149.

### 2.3 Name operators (sample, n_tset >= 70, same house number; labels used only to describe)
- One added token: true fillers (match rate 0.9-1.0) are the, inc, corp, co, ltd, corporation, llc, lp, center, services, service, company, and, foundation, federation, society, trust, council, board, authority, district, association, commission, sri, shri, smt, mr, dr. Decoy markers (match rate 0.000) are private (n=2,411), enterprises, industries, group, infratech, holdings, exports, overseas, ventures, pvt, foods, technologies, constructions, solutions, hotel, engineering, trading (India) and native-script trade words.
- One swapped token: llc<->inc 0.0, private->public 0.0, tech<->technologies 0.006/0.0, limited->llp 0.0, pvt<->private 0.0; but pc->inc 0.97, lp->llc 0.96, private->center 0.996, limited->ltd 0.91.
- `er_norm` strips legal words and maps tech->technologies, so name_core erases these markers.
- Label-free recovery: score(t) = (n_D + 1)/(n_D + n_0 + 10), counting pairs where t is the added token and hd in D vs hd = 0 (|A|,|B| <= 2). It ranks the US decoy vocabulary on top with no labels: lakeside, midtown, eastgate, westgate, southside, riverside, greater, northside, central (0.97-0.98), holdings 0.97, group 0.95, north/east/south/west, uptown, downtown, valley, metro, harbor, coastal, highland, summit (0.82-0.93). It ranks fka, formerly, nee, dba, aka, id at the bottom (~0.01). India is noisier (public/overseas/holdings/group/infratech 0.62-0.65) because India decoys keep the house number more often. The same score computed on test France pairs gives France its own marker list.

## 3. Build spec
- New side-car `src/er_feat6.py` (needs human approval: src edit), keyed by (s1_idx, pool_idx), for all candidate pairs of a split:
  - house: hd = int(house_p) - int(house) (NaN if either is non-numeric); hd_D = hd in D; h_suf = one number is a proper suffix of the other;
  - names: conservative token sets (NFKD, marks stripped, lowercase, split on non-alphanumerics, legal words kept); A = S1-only, B = pool-only, nA, nB;
  - label-free scores per country from that split's own pairs; dm_add = max score over B, dm_drop = max over A, dm_swap = (a>b) score when |A| = |B| = 1.
- Add them to stage 1 and stage 2 (a better stage 1 also sharpens the feat4 competition features); retrain both stages as usual.
- Cost (derived): feature build ~10-15 min per split on 8 cores, run in 10M-pair batches (peak ~12 GB); the 10% sample took 82 s at 6 GB. Retraining is the usual 006 pipeline time.

## 4. Risks and interactions
- Score scale shift: the test has ~2x decoys, so test-derived scores are inflated. Use train-derived scores for US/India and test-derived scores only for France, or use rank-normalised scores. Keep hd_D (fixed set, scale-free) as the primary signal.
- The features are pair-local (no cross-candidate aggregation), so they do not share the coherence feature's failure mode. They should lower the house-conflict share of emitted test pairs (the guard metric), not raise it.
- Complementary to er_feat5 (IDF masses measure rarity, not the generator's decoy vocabulary; "private" is common yet a perfect decoy marker).
- House-number parsing: hd needs `house` from er_norm; France "bis/ter" is handled there already.
